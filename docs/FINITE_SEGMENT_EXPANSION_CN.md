# MiniMax H3 插件内置有限分段展开

有限分段路径用于段数已经确定的长视频任务。`MiniMax H3 有限分段展开`只生成规划，
`MiniMax H3 有限分段采样`再通过 ComfyUI 官方节点展开机制，把每一段展开成普通无环
执行图，因此不依赖 `Loop`、`Loop Variable`、`Close Loop` 或 PR #15923。

## 连接方式

1. `MiniMax H3 素材规划台`不要连接“提示词序号”，把完整“素材规划参数”连接到本节点。
2. 把所有 H3 分段提示词粘贴到“有限分段展开”的 `segment_prompts`，相邻段使用独占一行的
   `--- SEGMENT ---`分隔。
3. `分段数量`必须同时等于：提示词段数、素材规划台设置的分段数。
4. 把“有限分段规划”连接到 `MiniMax H3 有限分段采样`。
5. 把模型、CLIP、视频 VAE、音频 VAE、原生采样器和调度器连接到“有限分段采样”。
6. 将采样节点的“合并画面”和“合并音频”接到 `Create Video`，再连接 `Save Video`。

这样提示词和素材编排可以先独立检查；更换采样器、步数或调度器时不需要重建分段规划。

## 内部执行顺序

每一段都会依次执行：

`分段选材 → H3规划编码 → 上段Latent尾部续接 → 线性时间遮罩 → 采样 → AV解码 → 删除重复区`。

第二段起，上一段的完整 sampled AV latent 会直接参与下一段开头，不经过 RGB 解码再编码。
重叠帧自动向下对齐到 H3 合法长度（1 或 `17k+5`）；对应时间遮罩在重叠 token 内从
0 线性过渡到 1，重叠区之后保持 1。最终画面和音频按段号依次拼接，后一段开头的重复
重叠区会被删除。

## 当前边界

- 当前版本一次最多展开 12 段。
- 这是“固定段数一次运行”的第一版，不包含磁盘项目缓存、片段挑选或单段重跑。
- 合并画面在最终保存前会保留在内存中。高分辨率、长时长或较多分段可能占用较多内存；
  初次测试建议从 2～3 段、较低分辨率开始。
- `末段 sampled latent`仅表示最后一段的完整 AV latent，用于检查或继续实验，不是整条
  长视频的合并 latent。

提示词格式请遵循[循环分段提示词 Agent 规范](MiniMax_H3_循环分段提示词_Agent规范.md)。

## 已验证的小型实测

在 512×288、每段56帧、两段、请求/实际重叠22帧、1步的结构测试中，最终输出严格为
`56 + (56 - 22) = 90`帧，24fps、带音频。复现脚本位于
`tests/experiments/run_minimax_h3_finite_segments.py`。
